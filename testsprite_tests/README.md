# TestSprite test suite

These scripts were generated by TestSprite AI and are kept as a regression and
coverage reference. They are standalone Python scripts, not part of the Node
test suite and not part of CI.

## What is here

- `TC0xx_*.py`: API tests driven with `requests` (they call the API through the
  Vite proxy at `http://localhost:5173/api`).
- `TC0xx_*.py` with Playwright imports: frontend flow tests against the running
  SPA at `http://localhost:5173`.
- `testsprite_backend_test_plan.json`, `testsprite_frontend_test_plan.json`:
  the generated plans.
- `standard_prd.json`: the product requirements snapshot used to derive the
  tests.
- `testsprite-mcp-test-report.md` and `.html`: the run report.

## How to run

1. Start the app and seed demo data:

   ```bash
   pnpm install
   pnpm --filter @makaan/api seed
   pnpm dev
   ```

2. Install the Python dependencies and the Playwright browser:

   ```bash
   python3 -m pip install -r testsprite_tests/requirements.txt
   python3 -m playwright install chromium
   ```

3. Run a single script:

   ```bash
   python3 testsprite_tests/TC001_get_apihealth_returns_service_status.py
   ```

Each script prints `TEST PASSED` and exits 0, or prints the failure and exits
non-zero.

## Known limitations

- The frontend scripts share one live database, so tests that end or close a
  tenancy can block later tests that need an active tenancy. Run them in a fresh
  seeded state, one flow at a time.
- Several frontend cases in the report failed on runner tunnel timeouts and
  hydration latency rather than on product behaviour. Running against a built
  preview (`pnpm --filter @makaan/web build && pnpm --filter @makaan/web preview`)
  is faster than the dev server.
- The export test expects on-screen feedback; the settings page now shows a
  toast when the download starts.
